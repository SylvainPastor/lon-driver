# u61 — Using an Echelon/EnOcean USB LON Dongle on Linux

This document describes how to build, load and test the **u61** driver to use a
parallel-USB (FTDI) LON dongle (Ex. a **TP/FT-10** key, on a modern Linux system).

Validated on **Ubuntu 24.04, kernel 6.17.0-35-generic**.

## 1. Hardware

The `u61` (UMIP, TTY line discipline **27**) driver targets the FTDI-based USB
LON interfaces: **U10 FT Rev B, U20 PL, U60 TP-1250, U70 PL**.

A typical TP/FT-10 dongle enumerates like this:

```
usb 1-2: New USB device found, idVendor=0920, idProduct=7500
usb 1-2: Product: Echelon USB Network Interface
usb 1-2: Manufacturer: Echelon
ftdi_sio 1-2:1.0: FTDI USB Serial Device converter detected
usb 1-2: Detected FT232B
usb 1-2: FTDI USB Serial Device converter now attached to ttyUSB0
```

The FTDI chip is bound by `ftdi_sio` and exposed as **`/dev/ttyUSB0`**.

> A serial-USB (CDC-ACM, `/dev/ttyACM*`) dongle such as the **U10 Rev C / U60 FT**
> uses the **u50** driver (line discipline 28) instead.

## 2. Prerequisites

```bash
sudo apt install build-essential linux-headers-$(uname -r) libsystemd-dev
```

* `gcc` / `make`
* Kernel headers matching the running kernel (`/lib/modules/$(uname -r)/build`)
* `libsystemd-dev` (the `lonifd` daemon calls `sd_notify`)
* **Secure Boot** must be **disabled**, or the unsigned `u61.ko` module must be
  signed — otherwise `insmod` fails with *"Key was rejected by service"*.
  Check with: `mokutil --sb-state`

## 3. Build

From the repository root:

```bash
make u61        # build the u61.ko kernel module
make lonifd     # build the lonifd daemon
# or simply:  make     (builds u61 + lonifd)
```

Artifacts:

* `u61/u61.ko`
* `lonifd/lonifd`

Clean everything with `make clean`.

## 4. Load and test the dongle

The driver registers a TTY *line discipline*. The `lonifd` daemon opens the
serial device, attaches the line discipline (which creates a `lonX` network
interface), then reads the Neuron ID and transceiver type from the dongle.

```bash
# 1. Load the kernel module
sudo insmod u61/u61.ko
lsmod | grep u61
sudo dmesg | tail -n 15

# 2. Start the daemon (ldisc 27 is auto-selected for a ttyUSB* device)
sudo ./lonifd/lonifd -d /dev/ttyUSB0 -l 27 &

# 3. Inspect the result
sleep 5
ip -d addr show | grep -iA5 lon
journalctl -t echlonifd -n 20 --no-pager
```

### Expected result

A network interface **`lon0`** (or `lonX`) appears, and the daemon logs the
Neuron ID and transceiver type, e.g.:

```
echlonifd: Transceiver ID for lon0: TP/FT-10
echlonifd: Neuron ID for lon0: 03:0a:...:...
echlonifd: Assigning 44.1.1.125 to lon0
```

At that point the dongle is working: applications can send/receive LON traffic
over the `lonX` interface (raw `AF_PACKET` socket, EtherType `0x8950`).

### Useful one-off queries

```bash
sudo ./lonifd/lonifd -n lon0     # print the Neuron ID
sudo ./lonifd/lonifd -x lon0     # print the transceiver type
```

## 5. Unload / cleanup

```bash
sudo pkill lonifd      # closing the tty detaches the ldisc and removes lonX
sudo rmmod u61
```

## 6. Troubleshooting

| Symptom | Cause / fix |
|---------|-------------|
| `insmod: Key was rejected by service` | Secure Boot is on: disable it or sign the module. |
| `lonifd` hangs, no Neuron ID logged | The dongle is not answering on this driver/baud. It may be a serial-USB (CDC-ACM) device => use the **u50** driver (`-l 28`, `/dev/ttyACM0`). |
| No `lonX` interface created | Check `dmesg` for module load errors and confirm the device node (`ls -l /dev/ttyUSB*`). |
| `insmod: File exists` | Module already loaded, `sudo rmmod u61` first. |

## 7. Notes

* Line disciplines: **u61 = 27**, **u50 = 28**.
* Baud rate used by `lonifd` for u61 is **460800** (`BRATE_U61a`).
* The default per-interface IP is `44.1.1<N>.125/24` (configurable via the
  `ltip_obd_prefix` sysfs/conf entry).
